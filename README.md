# STUDIO · 工业设计作品集（纯前端）

极简、低饱和、大留白的工业设计作品集网站。**纯 HTML + CSS + 原生 JavaScript，无后端、无数据库、无构建步骤**。作品数据保存在浏览器本地存储（localStorage），可直接双击打开，也可放到任意静态网页服务器。

适合放：产品渲染图、Rhino / NX 建模图、香水瓶包装项目等。

---

## 一、文件结构

```
.
├── index.html    # 页面骨架（导航 / 视图容器 / 弹窗 / 灯箱）
├── styles.css    # 极简高级风格样式（响应式 / 动效）
├── app.js        # 全部逻辑：路由 / 本地存储 / 上传 / 后台
└── README.md     # 本说明
```

> 三个文件放同一目录即可，**不要拆开**。

## 二、怎么运行

### 方式 A：直接双击（最简单）
双击 `index.html`，用浏览器（Chrome / Edge / Safari / Firefox）打开即可。
首次打开会自带 3 个示例作品和一份示例资料，可在后台删除、替换。

### 方式 B：本地静态服务器（推荐，行为最稳定）
在文件夹内执行任意一种：

```bash
# Python（多数系统自带）
python -m http.server 8080

# 或 Node
npx serve .
```

然后浏览器访问 `http://localhost:8080`。
用服务器方式打开能避免个别浏览器对 `file://` 的限制，体验最一致。

### 部署到公网
把这三个文件上传到任意静态托管即可：GitHub Pages、Vercel、Netlify、Cloudflare Pages、对象存储（OSS/COS/S3）静态网站，或公司内网一台普通网页服务器。**不需要任何后端环境。**

## 三、管理员入口在哪

普通访客打开网站 **只能浏览**，看不到任何上传 / 删除 / 编辑按钮。

管理员入口是**隐藏的**：在网站页脚**右下角有一个极小的圆点 `·`**（默认半透明，鼠标移上去才会变清晰），点击它即可弹出登录框。

> 也可以直接访问 `#/admin` 锚点触发，但页脚圆点是最隐蔽的入口。

登录后进入后台，可：
- **新增作品**：填写标题、简介，拖拽上传图片（第一张自动作为封面，可改），添加参数（键值对）。
- **编辑 / 替换**：在「作品管理」里点某件作品的「编辑」，可增删图片、改封面、改文字。
- **删除作品**：点「删除」。
- **编辑资料**：在「资料编辑」里改首页名称、头衔、自我介绍、头像（首页 / 关于页同步更新）。
- 后台右上角显示「本地已用 X MB」，方便你掌握存储占用。

退出后台点「退出」即可；登录态只在当前标签页会话有效，关掉标签页即自动退出。

## 四、管理员密码在哪改

打开 `app.js`，最上方配置区第一行：

```js
const ADMIN_PASSWORD = "design2026";   // ← 改成你自己的密码
```

把 `design2026` 改成任意密码，保存即可。**改完需要重新刷新网页生效。**

⚠️ **安全性说明（重要）**：这是纯前端校验，密码就写在前端代码里。它能挡住「随手乱点」的普通访客，但**任何懂技术的人都能在源码里看到密码**，也能直接改浏览器本地存储。所以：

- 用于个人作品集、不想被陌生人误改——足够。
- 如果你需要**真正的权限保护**（别人绝对改不了），必须上后端鉴权（见第六节升级方案）。

## 五、数据存储与同步说明（必读）

本站点采用 **GitHub 作为云端数据库**，数据不再只活在某一台设备：

- **访客 / 任何设备**：打开网页即从 GitHub 读取 `data.json`（公开、无需登录），看到的是最新作品集。
- **管理员保存时**：作品会**自动推送到 GitHub**，因此手机加了作品、电脑刷新就能看到，且**清缓存 / 换设备也不会丢**（数据在 GitHub 上）。
- **本地缓存**：浏览器本地存储仅作为离线缓存；重载时采用「合并」策略——本地独有且未同步的作品**不会被云端数据覆盖**（修复了早期版本「重载即丢失」的问题）。

**关于 GitHub Token（写权限）：**
- 第一次在某台设备进后台「设置」里填入 Token 后，会**记住在该设备浏览器**（localStorage），之后无需重填。
- 若某台设备尚未填 Token，它仍能正常**浏览**，但新增/修改无法同步到云端（只存本地），此时在「设置」里补填 Token 会**立即把本地未同步的作品推上去**。
- Token 仅用于写入；访客读数据不需要 Token。

**仍需注意的两点：**
1. **容量**：GitHub 单文件上限 100MB，足够用；但图片仍建议用压缩后的（站点已自动压到 1600px / JPEG 0.82）。
2. **Token 安全**：Token 存在该设备浏览器里。公用电脑上用完可到「设置 → 清除」；也可随时在 GitHub 撤销该 Token，不影响网站运行。

> 这是「轻量、零成本、可永久托管」方案的最佳折中。若需要多管理员、正式账号体系，见下一节升级方案。

## 六、想永久保存作品？升级方案

按成本从低到高：

| 方案 | 改动量 | 效果 |
|---|---|---|
| **A. 导出 / 备份** | 无代码 | 定期把 `localStorage` 里的 `idp_works_v1` 备份成 `.json` 文件；丢了可导入恢复（可后续加「导出/导入」按钮）。 |
| **B. GitHub + 静态站** | 小 | 作品图放仓库、元数据写进 `works.json`，部署到 GitHub Pages。省本地存储、换设备可见，但仍无权限控制。 |
| **C. 后端 + 数据库（真权限）** | 中 | 加一个轻后端（Node/Express、Python/FastAPI、或 Serverless 函数）+ 数据库（SQLite / Supabase / Firebase）。上传走后端、密码走**服务端校验 + 登录令牌（JWT/Session）**。这是唯一能「别人绝对改不了」的方案。 |
| **D. 现成 CMS** | 小 | 直接用 Sanity / Strapi / Contentful 等，前端只负责展示，内容与权限交给平台。 |

**最小可行升级（保留现有前端、加真权限）**：把 `app.js` 里 `saveWorks/loadWorks` 换成 `fetch('/api/works')` 调用；新增一个约 100 行的后端做「读=公开、写=校验管理员令牌」。需要我直接帮你出这套后端模板，告诉我你偏好 Node 还是 Python。

## 八、常见问题

- **图片上传后很糊？** 默认压缩到 1600px。若要更高清，改 `app.js` 里的 `MAX_DIM`（如 2400）；但会更占本地空间。
- **想换默认示例作品？** 后台逐个「编辑 / 删除」即可；或删掉浏览器里本站点数据后重新打开会重置回示例。
- **灯箱打不开？** 确认用浏览器打开（非某些内置预览器），且 `index.html` 与 `app.js`、`styles.css` 在同一目录。
